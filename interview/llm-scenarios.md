## 1. 完整讲一遍 RAG 链路，瓶颈在哪一环？

**答题要点**
- 链路：数据接入 → 清洗 → 切片 → 向量化 → 索引存储 → 召回 → 过滤重排 → 上下文组装 → 生成 → 评测
- **瓶颈通常不在模型，而在切片和检索策略**——切片差导致召回差，召回差生成必然飘
- 元数据要保留（来源、分类、语言），用于过滤

## 2. 切片策略怎么定？chunk size / overlap 取多少？

**答题要点**
- 优先按**结构**切（标题 / 段落 / 函数），其次递归分块，避免用固定字符数硬切
- 常见取值：chunk 200–800 token，overlap 10–20%
- 表格、代码块要单独处理，不要切碎
- **做对比实验，用评测集选最优**，而不是拍脑袋

## 3. 混合检索为什么需要？Rerank 的作用和代价？

**答题要点**
- 纯向量检索对**专有名词、缩写、数字、精确匹配**很弱 → 加 BM25 关键词召回补齐
- 两路结果融合：RRF（倒数排名融合）或加权求和
- Rerank 用 cross-encoder 精排，把 Top 50 压到 Top 5，**代价是延迟和算力**，所以要限制候选数量

## 4. 知识库频繁更新，怎么避免全量重算 embedding？

**答题要点**
- **不要用字符偏移定位片段**（前面删一个字，后面全变）
- 按结构锚点切块 → 每块计算 hash（内容指纹）
- 更新时对比新旧 hash 列表 → 只对变化块做删除 + 重算
- chunk ID 要尽量稳定，元数据要能定位到文档 / 章节 / 片段

## 5. SSE 流式中用户断线，重连后怎么补流？

**答题要点**
- 拆成两层：实时推送 + **可恢复推送**
- 每条事件带**递增 event_id**，同时写入可回放存储
- 客户端重连时带上 `Last-Event-ID`，服务端先补发缺失区间，再继续实时推送
- 存储选型：轻量用 Redis Stream，稳妥落 MySQL（便于审计回放）
- **只靠内存不行**——多实例会丢

## 6. 多实例部署下，怎么保证同一会话只有一个执行者？

**答题要点**
- 目标不是保证 Agent 协作，而是保证**同一会话的唯一执行权**
- 按 `session_id` 加 Redis 分布式锁（SETNX + 过期 + 看门狗续期）
- 要防的场景：用户刷新/重试导致重复起跑、多端同时订阅导致重复推流、断线重连时补发与实时推送交织导致乱序
- **区分部署形态**：单实例用进程内互斥即可；多实例必须分布式锁

## 7. Agent 的状态怎么设计？在哪更新？怎么判断分支？

**答题要点**
- 状态分三类：
  - **会话基础状态**：session_id、用户信息、难度、当前题号、最后活跃时间
  - **过程状态**：最近问答历史、当前话题、累计得分、下一步动作提示
  - **控制状态**：是否停止、是否超时、是否取消、错误原因
- 分支判断放在**评估节点**：回答好 → 加深追问；一般 → 继续当前话题；偏弱 → 降难度或换话题
- 收口条件：达到最大轮数或用户退出

## 8. 多 Agent 怎么编排？

**答题要点**
- 结构：**主控 Agent + 专家 Agent**，职责分离才可控
- 主控负责节奏调度（开场、推进、切换、收尾），不自己生成所有内容
- 专家各管一域（如技术深挖、项目核验），主控在合适时机调用并原样透传输出
- 一句话总结：**主控负责调度，专家负责深挖**

## 9. 为什么选 LangGraph / Dify？边界在哪？

**答题要点**
- ⚠️ **关键不是踩谁捧谁，而是把选型和业务需求绑定**
- 要能讲清这几个维度：编排复杂度（是否需要显式图 / 状态机）、流式支持、可观测性埋点、团队语言栈、部署与运维成本、二次开发自由度
- 举例：简单链路用 Agent Runner 流式输出就够；复杂链路用 Graph 把状态机显式化，方便分支、循环和收口

## 10. 怎么降低 token 成本和首字延迟？

**答题要点**
- **语义缓存**：相似请求直接命中（要定相似度阈值，防误命中）
- **精确缓存**：按 prompt hash 缓存
- **模型分级路由**：简单问题走小模型甚至本地模型，难题才上调大模型
- **上下文压缩**：历史裁剪、摘要压缩、只带相关检索片段
- **并行化**：检索与预处理并行，减少串行等待
- 首字延迟靠流式输出改善**体感**

## 11. 怎么评测 RAG 效果？

**答题要点**
- **自建评测集**：50–100 条问答对（这是最稀缺的能力，大多数候选人没有）
- 检索侧指标：Recall@k、MRR、命中率
- 生成侧指标：忠实度（faithfulness）、答案相关性、引用准确性
- 工具：RAGAS，或 LLM-as-judge
- 做 **A/B 对比**不同切片 / 检索方案，形成回归测试

## 复盘：这一类面试的共同套路

从真实面经总结出来的规律：

1. **场景题一环扣一环**，没真做过很难临场圆出来
2. 面试官会**从一个点一路追问**：接口链路 → 数据流 → 依赖组件 → 异常与兜底
3. 所以必须**复习整个项目架构**，而不是背零散知识点
4. **能讲清"为什么这么选、边界在哪"比"用了什么"重要得多**
